# OwnTracker

אפליקציית ווב אישית למעקב אחר שינויים בחיים. ממשק מלא בעברית, מימין לשמאל, עם התאמה למחשב ולטלפון. ברירת המחדל היא התחברות ל־Supabase; קיים גם מצב SQLite מקומי.

להמשך הפיתוח ממחשב אחר: ראו [DEVELOPMENT.md](DEVELOPMENT.md), הכולל מצב נוכחי, בדיקות ושלבים שנותרו.

## התקנה בגלקסי וסנכרון — מצב נוכחי

נוספו הגדרות PWA: manifest, אייקונים ל־Android ופתיחה בחלון עצמאי. כאשר Chrome מאפשר התקנה, יוצג כפתור ״התקנת האפליקציה״. אפשר גם להשתמש באפשרות ההתקנה בתפריט Chrome. אין צורך בפרסום בחנות Play עבור מסלול התקנה זה. [הוראות Google להתקנת אפליקציית ווב ב־Android](https://support.google.com/chrome/answer/9658361?co=GENIE.Platform%3DAndroid).

**קוד ההתחברות והסנכרון לענן נכתב, אך עדיין אין כתובת ציבורית להתקנה בטלפון ולא הושלמה בדיקת סנכרון מול חשבון אמיתי בשני מכשירים.** הכתובת `127.0.0.1` מתייחסת למכשיר שבו פותחים אותה; בגלקסי היא לא מצביעה למחשב. שרת הפיתוח נשאר מקומי בלבד. לפרסום משתמשים בתיקיית האתר הסטטי, כמפורט בהמשך.

לפי בחירת המשתמש, היעד הוא אותו חשבון ואותם נתונים בטלפון ובמחשב. להשלמתו נדרשים:

1. פרויקט Supabase כבר הוגדר ב־`public/config.js`. לתוכנית Free יש מכסות שימוש, ופרויקט לא פעיל עשוי להיות מושהה. [תנאי התוכנית](https://supabase.com/pricing).
2. `supabase/setup.sql` יוצר טבלאות, RLS ופונקציית API עם בדיקות בעלות וגרסאות. המשתמש אישר שהריץ אותו בהצלחה. נדרש ליצור משתמש אישי ב־Authentication → Users → Add user, ולהתחבר דרך האפליקציה. אין צורך למסור למפתח את סיסמת המשתמש.
3. פרסום האתר בכתובת HTTPS נגישה מהטלפון, ואז בדיקת שמירה במכשיר אחד וטעינה במכשיר השני.
4. פתיחת הכתובת בגלקסי באמצעות Chrome ובחירה בהתקנה דרך הכפתור או תפריט הדפדפן.

בחיבור לפרויקט Supabase אחר, מעדכנים ב־`public/config.js` את Project URL ואת ה־Publishable key הציבורי בלבד ומריצים בו את קובץ ה־SQL. אין להכניס לריפו סיסמת DB או מפתח secret/service_role. יש לבדוק הפרדה בין משתמשים לפני שימוש בנתונים אמיתיים.

הוספת PWA אינה מעתיקה את בסיס הנתונים לטלפון ואינה מאפשרת מילוי ללא חיבור. הנתונים המקומיים שכבר נשמרו נשארים בקובץ SQLite; העברתם לענן תידרש כחלק מחיבור הסנכרון.

## הפעלה

נדרש Node.js בגרסה 24 ומעלה. האפליקציה עצמה משתמשת רק במודולים המובנים ב־Node.js, ולכן אין צורך בהתקנת חבילות כדי להפעיל אותה.

```powershell
git clone https://github.com/ozhar1248/OwnTracker.git
cd OwnTracker
npm start
```

פותחים בדפדפן: http://127.0.0.1:3000

השרת מאזין למחשב המקומי בלבד ומגיש את הממשק. במצב ברירת המחדל הממשק מתחבר ישירות ל־Supabase ודורש אימייל וסיסמה של משתמש האפליקציה (לא פרטי הכניסה ללוח הבקרה של Supabase). הנתונים מתרעננים מדי 20 שניות כשהאפליקציה גלויה ואין טופס פתוח, ובחזרה לאפליקציה. פעולות שמירה דורשות חיבור; אין תור שמירה לא מקוון.

לשימוש בגרסת SQLite המקומית בלבד, ללא Supabase:

```powershell
$env:OWNTRACKER_MODE = 'local'
npm start
```

ב־macOS/Linux: `OWNTRACKER_MODE=local npm start`. להסרת הבחירה ב־PowerShell: `Remove-Item Env:OWNTRACKER_MODE`.

## פרסום האתר לטלפון

```powershell
npm run build
```

התיקייה `site/` תכיל את האתר המוכן לפרסום באחסון סטטי עם HTTPS, למשל באמצעות Netlify Drop. מעלים רק תיקייה זו, לא את כל הפרויקט. אין צורך להריץ שרת Node באחסון. הקובץ `_headers` כולל הגדרות אבטחה ל־Netlify/Cloudflare Pages.

לאחר פרסום, פותחים את אותה כתובת במחשב ובגלקסי ומתחברים לאותו חשבון. ב־Chrome בטלפון בוחרים בהתקנה דרך כפתור האפליקציה או תפריט הדפדפן. פרסום האתר ובדיקת התקנה במכשיר אמיתי עדיין לא בוצעו.

פורט חלופי:

```powershell
$env:PORT = '3001'
npm start
```

## מה כלול

- יצירה ועריכה של שינוי: כותרת חובה, תיאור רשות ותדירות יומית / שבועית / חודשית.
- מילוי יומי עם תאריך, בוצע / לא בוצע / אחר והסבר חופשי.
- ברירת המחדל היא היום. אפשר להשלים דיווחים היסטוריים, עד לתאריך היום.
- זיהוי דיווח קיים והצגת חלון המציע מעבר לעריכתו. אין דריסה אוטומטית.
- מניעת דריסת דיווח או הגדרת שינוי שעודכנו בחלון אחר באמצעות בדיקת גרסה.
- טבלת שינויים מול ימים, עם תצוגה שבועית כברירת מחדל, וכן תצוגות יומית וחודשית.
- סימוני ✓ / × / ○ / תא ריק, ואייקון קטן כאשר נשמר הסבר.
- מחיקה לוגית ששומרת את הדיווחים ואת תקופת הפעילות לצורך תצוגה ודוחות היסטוריים.
- דוחות יומיים, שבועיים וחודשיים בטקסט קריא ל־AI, עם העתקה ללוח והורדת TXT בעברית.
- ייצוא מלא של הנתונים לקובץ JSON. הייצוא אינו כולל ממשק ייבוא.

## כללי המעקב והדוח

- שבוע מתחיל ביום ראשון ומסתיים בשבת. חודש הוא חודש קלנדרי.
- תדירות היא היעד שהמשתמש הגדיר; דיווח משויך תמיד לתאריך מסוים. שינוי שבועי/חודשי אינו מחויב בביצוע בכל יום.
- חוסר מילוי אינו ״לא בוצע״. ימים עתידיים וימים מחוץ לתקופת הפעילות מסומנים בקו ואינם נחשבים לחוסר מילוי.
- שינוי מתחיל ביום יצירתו. דיווח לתאריך מוקדם יותר מרחיב את תקופת המעקב לאחור.
- שינוי שנמחק נחשב פעיל עד יום המחיקה, כולל יום המחיקה. לכן הוא יכול להופיע בטבלה של השבוע הנוכחי גם לאחר מחיקתו.
- אפשר לערוך ולהשלים דיווחים היסטוריים של שינוי שנמחק, עד יום המחיקה. אין יצירת דיווחים לאחריו.
- דוחות כוללים רק שינויים שתקופת פעילותם חופפת לטווח הנבחר. הם כוללים סטטוסים, הסברים וחוסרים, וכן הנחיות למודל AI.
- כותרת, תיאור ותדירות בדוחות משקפים את ההגדרה האחרונה. גרסאות קודמות של הגדרת השינוי אינן נשמרות.
- במצב ענן, התאריך ״היום״ נקבע בשרת Supabase לפי `Asia/Jerusalem` כדי שיהיה אחיד בין מכשירים. במצב מקומי הוא נקבע לפי אזור הזמן של המחשב שמפעיל את השרת. חישובי הטווחים מתבצעים על תאריכים קלנדריים ללא הסטה עקב שעון קיץ.
- שום מידע לא נשלח למודל AI מתוך האפליקציה. המשתמש מעתיק או מוריד את הדוח ובוחר למי להעביר אותו.

## בסיס הנתונים וגיבוי

במצב ענן, הנתונים נשמרים ב־Supabase PostgreSQL תחת החשבון המחובר. ניתן לייצא JSON מתוך האפליקציה. ההתחברות נשמרת בדפדפן; הסיסמה עצמה אינה נשמרת בו על ידי האפליקציה.

במצב מקומי משתמשים ב־[SQLite חינמי](https://www.sqlite.org/copyright.html). נשמר קובץ `data/owntracker.sqlite`, שנוצר אוטומטית בהפעלה הראשונה. השמירה אינה תלויה בזיכרון הדפדפן; רענון, סגירת הדפדפן והפעלה מחדש של השרת אינם מוחקים נתונים. הקובץ אינו עולה ל־GitHub ולא מועבר אוטומטית לענן.

לגיבוי שניתן לשחזר במלואו: עצרו את השרת באמצעות Ctrl+C והעתיקו את תיקיית `data` למקום בטוח. לשחזור, כשהשרת כבוי, החליפו את תיקיית `data` בעותק הגיבוי. ייצוא JSON מהמסך שימושי לקריאה/העברה של הנתונים, אך אין כרגע מנגנון שחזור JSON בתוך האפליקציה.

אפשר לבחור מיקום אחר באמצעות `OWNTRACKER_DB`. אין לפרסם את קובצי בסיס הנתונים בריפו. התיקייה `data` כלולה ב־`.gitignore`.

נעשה שימוש ב־[`node:sqlite`](https://nodejs.org/docs/latest-v24.x/api/sqlite.html), המובנה ב־Node.js 24. בחלק מגרסאות Node.js מוצגת הודעת ExperimentalWarning; זו הודעת סטטוס של המודול.

## בדיקות

להתקנת כלי הבדיקה במחשב חדש: `npm ci`. ההרצה הרגילה והבנייה אינן דורשות חבילות חיצוניות.

```powershell
npm run check
npm test
```

הבדיקות משתמשות בבסיסי נתונים זמניים ומכסות שמירה וטעינה מחדש, עריכה, מחיקה לוגית, דיווחים כפולים, עדכונים מקבילים, קלט לא תקין, טווחי תאריכים ותוכן הדוחות.

בדיקות ממשק ב־Playwright (דורשות התקנת חבילות הפיתוח והדפדפן):

```powershell
npm install
npx playwright install chromium
npm run test:ui
```

## מבנה

- `server.js` — שרת HTTP מקומי ו־API.
- `store.js` — SQLite, אימות קלט ושמירת גרסאות לצורך מניעת דריסות.
- `public/domain.js` — טווחי תאריכים, תקופות פעילות ויצירת דוחות.
- `public/cloud-client.js` — חיבור ל־Supabase Auth/REST, רענון התחברות ושמירת גרסאות.
- `public/config.js` — כתובת הפרויקט ומפתח publishable ציבורי; ללא סודות.
- `supabase/setup.sql` — סכמת הענן, מדיניות הרשאות ו־RPC.
- `scripts/build-site.js` — יצירת תיקיית פרסום סטטית.
- `public/` — ממשק HTML, CSS ו־JavaScript, ללא שירותים חיצוניים או CDN.
- `tests/` — בדיקות לוגיקה, API וממשק.
